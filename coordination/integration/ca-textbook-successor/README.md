# California textbook native successor

This package implements the PR304 successor of original PR225 as a separate, bounded non-live contract for the 35 California G6–G12 primary chapter openers and their 105 chapter checks. Its base is exactly `32f53da1b13b2c1fd28ae4eec1807fd355cc4c17`. The old v2.6 and Arkansas successor implementations, ledgers, evidence and workflows remain unchanged.

**Current implementation:** checker protocol `ca-textbook-successor.v2` prepares a new immutable attempt after the failed v1 attempt 001. Source S remains `98d086c83aa4d37d819d4121570b7526c8cb9c06`. The original R2/E/X commits, reviews, local failures and Ubuntu CI failures remain in Git ancestry and a verified external recovery bundle; they are not rewritten or transferred as new approval. The former attempt payload and temporary diagnostic workflow are absent from the new release tree so S→R remains the exact fixed checker inventory. Fresh checker reviews, new attempt-owned evidence, a new execution commit and complete public native runs are still required. A synthetic fixture or timing diagnostic is never candidate approval. Existing public `promotion:*` commands and historical selectors remain unchanged until separately reviewed activation.

- The 15 bitmap files remain retained artifacts. Each has explicit one-to-many semantic coverage witnesses: new middle-school openers and/or unchanged retained related lessons, with exact source bindings. No positional old/new bijection is assumed. The worker verifies every witness is a current primary/related member of the named topic and is reachable. The global inventory comparator checks the real row sets, all 35 new lessons and primary routes, all other 284 live references, and preserved old lesson/lab/figure/surface inventories. It requires the eight exact existing baseline failures and the two explicit retired-reference count failures. It returns `globalInventoryPassed=false`; this is scoped replacement accounting, not a waiver or green global audit.
- `repository.mjs` verifies real Git commits/parents/trees, clean index and materialized files, regular single-link files/modes, no grafts/replacements/shallow history, and no untracked writer content. Read-only snapshots are checked before and after observation. A full-tree filesystem failure is blocking; it is never replaced by checking only changed paths.
- `promotion.mjs` loads the strict parser from the anchored Git blob, verifies the exact checker bundle before importing it, removes inherited credentials/loader hooks from child execution, and runs only captured release code. The complete installed TypeScript tree binding is included in the dependency-inclusive bundle digest approved by both checker-freeze reviews, as well as the lockfile version/integrity and release ledger. Rebinding the installed tree and later ledger cannot reuse the previous reviews.
- `observer.mjs` reads an immutable snapshot, parses assignments without importing candidate/app code, and uses a checked-in, separately versioned derivative of the byte-pinned canonical graph observer. Its complete original/derived bindings and exact diff are recorded in `adapter-provenance.v1.json`; there is no runtime source rewriting. Its closed storage profile preserves all four raw `mediaOwnerErasure.ts` detections and separately classifies their exact unchanged source as non-module write/sync/enumeration; every unclassified operation still blocks. It rejects unresolved imports and unregistered loaders, requires all 35 bodies/snapshot reachable, requires the retired projection/candidates unreachable, and preserves other approved projections. It has no provider, database, network or deployment operation.
- `receipts.mjs` implements temporary-output-only Shadow, exact stored-blob transport, replay, distinct canonical/fresh/replay comparison, and non-live Closure/lifecycle-registry construction. Shadow rollback means deletion of its private temporary output only.

All authoritative JSON uses the bounded duplicate-key-rejecting UTF-8 parser. Before the unchanged legacy JSON consumers run, the worker strictly parses the complete canonical-discovery, directly served public, retained projection/candidate and actually reachable JSON set. Resolver JSONC remains with the unchanged authenticated TypeScript resolver parser. The fixed `schemas.json` is the only accepted schema collection; callers cannot supply a schema or widen permissions. Every passing output keeps `liveAllowed=false`.

Receipt `rawDigest` is the canonical-JSON self-digest of the receipt body excluding that field. `semanticDigest` excludes per-run metadata. The separate transport `sha256` always hashes the exact stored file bytes; these three hashes are not interchangeable.

## Failed-attempt recovery and marker-read cost

Version 2 derives the ledger at exactly `attempts/<attemptId>/checker-release.json`, validates the bounded attempt ID before the public bootstrap reads it, and requires the selected Manifest path to have the same prefix. There is no fallback to the v1 global ledger or another attempt. Every new attempt uses new first-add paths for evidence, reviews, asset-report references, Manifest, descriptor and receipts. It keeps complete failed-attempt ancestry while removing superseded payloads from the new fixed release tree. Existing R/E/X and review hashes remain historical records; all new candidate and review bindings are independently recomputed.

The first real v1 validation exceeded its 60-second outer deadline on both local Linux and Ubuntu CI; diagnostic full validations took about 63 and 62 seconds. A separate read-only A/B/B/A experiment found the marker loop reread 1,539 eligible files for each of 18 registry rows: 27,702 reads and approximately 18 seconds. Reading each file once and testing the same 18 marker sets required 1,539 reads and approximately 1.1 seconds, with identical complete correlation digests in all four measurements. The v2 implementation uses that file-first loop, keeps the same eligible extensions, raw marker semantics and per-row counting, propagates authoritative read failures, and retains all before/after snapshot, full-tree, parser and audit checks. It does not cache evidence across runs or skip a file. Existing operation and child deadlines remain unchanged; real v2 execution must demonstrate sufficient margin.

## Immutable phases

The coordinator must build each phase from actual source and actual evidence. No command here creates an approval record or a guessed future SHA.

1. **B → S: source.** B is the exact base above. Freeze the reviewed candidate source S and its tree. Every B→S path must be in `ALLOWED_SOURCE_PATHS` (plus the narrowly named PR225 session log). `candidate.files` includes all `CORE_FILES` and every changed allowed source file; removals are explicit. `sourceInventoryDigest` is SHA-256 of the raw `git ls-tree -r -z S` output. Both source-author and checker-author identity lists are required. Checker-freeze and finalization A11/A23 reviewers must be outside both lists. The A05 ownership-file delta is restricted to the two exact CCSS data pathspecs and their resolution checks; arbitrary ownership changes are rejected.
2. **S → R: checker release.** Add only the exact `releasePaths()` set after S; the namespace is absent at S. R is distinct from S. `BUNDLE_PATHS` defines the complete fixed executable/test/schema/library/lockfile set; each ledger entry records path, tracked mode, Git blob ID and raw SHA-256. `bundleDigest` is the canonical-JSON digest of `{ files: orderedFileBindings, dependencies: exactInstalledDependencyBindings }`. Both independent reviews approve this complete digest; executable dependency bytes cannot be changed through a later evidence-only ledger edit. Freeze R before obtaining A11/A23 checker-freeze reviews. The ledger does not yet exist at R.
3. **R → E: evidence.** First-add the selected attempt’s `checker-release.json` in E with the actual release identity, dependency binding and two independent checker-freeze review records/reports. Add actual candidate, disposition, registry, canonical audit, and seven role evidence records/reports. All review times must follow R and precede E. E is distinct from R. No source or checker file can drift in this phase, and the complete R→E delta must equal `collectEvidenceArtifacts()` at the fixed typed paths above.
4. **E → X: execution.** In the direct child X, first-add exactly `attempts/<id>/manifest.json` and `successor.json`. The Manifest requires `pullRequestNumber=304`; original PR225 is historical provenance. The descriptor binds the Manifest's raw bytes; the Manifest names the descriptor path without a circular hash. The future canonical Receipt must be absent. Native operations run from the clean, fully materialized X checkout.
5. **X → receipt storage.** Run validate, canonical Shadow and a distinct fresh/replay pair under X. Store their returned bytes in a later descendant commit, with only the canonical receipt and `receipts/*.json` paths changed. Each transport supplies the exact repository-relative path, storage commit and file SHA-256. Named storage trees may contain only registered receipt paths. The three exact regular `100644` blobs must persist unchanged through the admitted release, its exact main merge and finalization tree; missing, replaced, mode-changed and unregistered receipts block. Verification reads that Git blob, requires execution-time absence and genuine descendant storage, and runs a new replay under X.
6. **Activation and main.** Separately review the exact workflow and `scripts/promotion-required-check-ca-textbook-successor.mjs` activation, plus any bounded `activation/` evidence files. The release source can differ from X only by the receipt paths and this explicit activation inventory. Existing `promotion:*` mappings are not remapped by this package. The release must receive all seven named CI checks plus `promotion-shadow-gate` on PR304 (`pullRequestNumber=304`), and main must be the ordered merge `[B, release]` with exactly the release tree. Unsupported composition fails closed.
7. **Finalization storage.** After main and receipt storage, record four real A11/A22/A23/A25 finalization reviews, actual PR/main CI receipts and `finalization-input.json` in a descendant of that main commit. A11/A23 identities must be distinct and outside both source/checker author lists. Every finalization review must follow the release, main, both CI observations and all named receipt storage times, and precede finalization storage. The main CI record requires `pullRequestNumber=null`. Finalization storage permits only the bound evidence/report/input paths. From X, transport that exact input commit/path/hash to `finalize`. It re-verifies all three stored receipts through fresh replay, compares them, and returns a Closure plus a two-event lifecycle Registry. Persist and review these returned bytes separately; emitting them does not write the repository or activate live content.

A different base, new candidate semantics, checker code change, runtime drift, or changed global-baseline disposition requires a newly reviewed immutable contract/attempt. There is no “ignore failures”, “baseline-only”, arbitrary scope or caller-selected schema option.
