# Mainland PEP Primary Question Illustrations V1

This folder contains the S18 candidate-generation workflow for 1,200 Mainland PEP primary question illustrations.

The owner-approved default route is the Codex built-in GPT Image 2 loop: Codex calls `image_gen` one image at a time, and this local script handles queue selection, prompt packaging, latest-image import, manifest updates, validation, and review-package rebuilds. This route does not require `OPENAI_API_KEY`.

## Source Queue

- `../2026-05-27-S18-mainland-pep-primary-question-illustration-queue.jsonl`
- Expected total: 1,200 rows
- Need-level split: `core=700`, `recommended=400`, `optional=100`

## Commands

Check current Codex built-in generation status:

```bash
node coordination/content-qa/mainland-pep-primary-question-illustrations-v1/generate-question-illustrations.mjs --built-in-status
```

Print the next Codex built-in GPT Image 2 prompts. Smoke defaults to 24; routine batches should stay near 12 unless QA is stable:

```bash
node coordination/content-qa/mainland-pep-primary-question-illustrations-v1/generate-question-illustrations.mjs --next-built-in --count 12
```

Import an image generated by Codex built-in GPT Image 2:

```bash
node coordination/content-qa/mainland-pep-primary-question-illustrations-v1/generate-question-illustrations.mjs \
  --import-question-id pep-primary-p1-u-mc-001 \
  --import-source /Users/dongpinhu/.codex/generated_images/.../image.png
```

Import the newest image generated by Codex built-in GPT Image 2:

```bash
node coordination/content-qa/mainland-pep-primary-question-illustrations-v1/generate-question-illustrations.mjs \
  --import-latest \
  --import-question-id pep-primary-p1-u-mc-001
```

If a main candidate already exists for the question, import preserves the previous file as `questionId-v1.png`, `questionId-v2.png`, etc. The newly imported image becomes `questionId.png`.

Rebuild review and validation files from the current queue/results without generating or importing images:

```bash
node coordination/content-qa/mainland-pep-primary-question-illustrations-v1/generate-question-illustrations.mjs --rebuild-review
```

The legacy direct OpenAI API commands below remain available for a future owner-approved API batch path, but are not required for the Codex built-in route.

Dry-run the full queue without calling OpenAI:

```bash
node coordination/content-qa/mainland-pep-primary-question-illustrations-v1/generate-question-illustrations.mjs --mode full --dry-run
```

Generate one smoke image per family via OpenAI API:

```bash
OPENAI_API_KEY=... node coordination/content-qa/mainland-pep-primary-question-illustrations-v1/generate-question-illustrations.mjs --mode smoke
```

Generate all 1,200 candidates via OpenAI API after smoke QA passes:

```bash
OPENAI_API_KEY=... node coordination/content-qa/mainland-pep-primary-question-illustrations-v1/generate-question-illustrations.mjs --mode full
```

Useful controls:

- `GPT_IMAGE_MODEL`, default `gpt-image-2`
- `GPT_IMAGE_QUALITY`, default `medium`
- `GPT_IMAGE_SIZE`, default `1024x1024`
- `GPT_IMAGE_CONCURRENCY`, default `1`
- `GPT_IMAGE_MAX_RETRIES`, default `4`
- `GPT_IMAGE_DELAY_MS`, default `0`

## Codex Built-In GPT Image 2 Loop

1. Run `--built-in-status`.
2. Run `--next-built-in --count 24` for the initial smoke gap, then `--next-built-in --count 12` for routine batches.
3. For each returned item, send `prompt` to Codex built-in GPT Image 2.
4. Immediately run the returned `importCommand`.
5. Inspect the saved image with `view_image`.
6. Mark bad images as `revise` in `manual-review.csv`; the next `--next-built-in` run prioritizes `revise` rows.

Generation order is fixed: fill the 24-family smoke set first, then `core`, then `recommended`, then `optional`.
