- The current analytics data path always reads the app snapshot via `readDatabase()`.

## Resolution

- Added a teacher analytics Postgres projection hook in `lib/server/userStore/teacherOpsOperationsPersistence.ts`.
- Wired `lib/server/userStore.ts` so `getTeacherAnalyticsData()` first tries `getTeacherAnalyticsDataFromPostgresProjection()` and falls back to the app snapshot only when projection is unavailable.
- Added a bounded projection for teacher-owned class/student rows and overlaid Postgres hot activity rows from `practice_attempts`, `mistake_book_items`, and `learning_events`.
- Recomputed topic lesson progress from the merged attempt rows when hot attempts are newer, so teacher analytics does not show fresh activity with stale mastery.
- Kept `/api/teacher/analytics` and `/api/teacher/analytics/follow-up` contracts unchanged.
