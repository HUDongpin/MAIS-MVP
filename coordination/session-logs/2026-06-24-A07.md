## Analysis

- Root cause for the observed slow text reply is provider connectivity timeout from this machine to DeepSeek, not front-end rendering or typing animation.
- The UI waits for `/api/ai-tutor` to finish because text responses are non-streaming. When DeepSeek cannot connect, the user waits around 10-13 seconds before the server returns a friendly fallback.
- The route also has serial pre-provider work: authentication, rate-limit lookup, quota lookup soft timeout, database context soft timeout, and evidence/context assembly. These add overhead, especially on cold start.
- The current route sends the first DeepSeek text call with `thinking: disabled`, so the measured delay is not caused by DeepSeek high-reasoning mode.
- If provider output is malformed after a successful provider response, the route can issue a strict JSON retry and then a plain-text rescue call. That can multiply latency, but it was not the observed path today because provider connection timed out before returning any body.

## Remediation Implemented

- Added Qwen text fallback config support in `lib/server/llmProvider.ts`, including `QWEN_TEXT_MODEL` with fallback to shared Qwen/DashScope credentials and existing image model configuration.
- Added a lightweight in-process provider circuit breaker. A failed primary text provider opens immediately for 60 seconds, so the next request skips DeepSeek and goes directly to the reachable fallback.
- Added `AI_TUTOR_PRIMARY_FAILOVER_TIMEOUT_MS` with a default of 1500ms. When a fallback provider is configured, the primary attempt uses this short timeout instead of making the student wait the full provider timeout.
- Added AI Tutor SSE support for `Accept: text/event-stream`. The route sends an immediate `status` event and a final `final` event that preserves the original response status and JSON body.
- Updated `components/ai/AITutorProvider.tsx` to request SSE, parse the `final` event, and fall back to JSON parsing when tests or older deployments return `application/json`.
- Added live text QA latency gate metadata and configurable thresholds:
  - `AI_TUTOR_LIVE_TEXT_MAX_CASE_LATENCY_MS`
  - `AI_TUTOR_LIVE_TEXT_P95_LATENCY_MS`
