## Backend E2E Per-Run Isolation

### Session
- Session ID: S22
- Coordinating owner: S11 for backend E2E assertions and direct SQLite test access.
- Objective: Make backend E2E DB/output paths per-run isolated so parallel Playwright webServer runs do not delete each other's `.tmp/e2e` SQLite DB, Next build output, or trace artifacts.

### Plan
1. Inspect current `playwright.config.ts` and `tests/e2e/backend-api.spec.ts` for shared path assumptions.
2. Keep S11's backend assertion behavior intact; only route the direct SQLite helper through the same `HK_MATH_DB_PATH` that the webServer uses.
3. Update S22-owned Playwright config to derive a per-process run root, Next dist dir, temp tsconfig, SQLite DB path, and Playwright output/report dirs.
4. Run `npm run type-check` and targeted backend E2E verification.

### Results
- Root cause confirmed:
  - `playwright.config.ts` previously hardcoded `.tmp/e2e` for the SQLite DB and default Playwright artifacts, so parallel webServer runs could delete another backend suite's DB while `backend-api.spec.ts` was directly mutating it.
  - Initial per-run root attempt used `process.pid` directly, but Playwright evaluates config in multiple Node processes; the stable fix writes `PLAYWRIGHT_RUN_ID` and `PLAYWRIGHT_E2E_ROOT` back to `process.env` for child workers.
- Changes completed:
  - Added a stable per-run root in `playwright.config.ts`: `.tmp/e2e-run-<port>-<pid>` by default, overridable with `PLAYWRIGHT_RUN_ID` / `PLAYWRIGHT_E2E_ROOT`.
  - Moved default Next dist, Playwright temp tsconfig, SQLite DB, Playwright outputDir, and HTML report folder under that per-run root.
  - Passed the same absolute `HK_MATH_DB_PATH` to both the Next webServer and Playwright test process.
  - Kept the temporary tsconfig at the project root during `next build` for Next alias compatibility, but made the filename per-run and removed it before `next start`.
  - Kept S11 backend assertions intact and relied on the existing `HK_MATH_DB_PATH`-aware direct SQLite helper in `backend-api.spec.ts`.
- Checks run:
  - `npm run type-check`: passed.
  - `npm run test:backend`: passed, 4/4 after the final build-only temp-tsconfig cleanup.
- Notes:
  - `NO_COLOR` / `FORCE_COLOR` warnings still appear from Node during Playwright runs; they are cosmetic and did not affect the pass.
  - The run leaves artifacts under the generated `.tmp/e2e-run-*` directory as intended for failure/debug inspection, while root `tsconfig.playwright-<run>.tmp.json` files are cleaned during startup.
