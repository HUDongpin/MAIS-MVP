## Root-Cause Assessment

- Live production appears to be running the DeepSeek-oriented AI Tutor path, while the current dirty worktree contains newer Qwen-oriented status/chat work. This creates release/version-observability risk.
- The deployed/HEAD AI Tutor route has a default `AI_TUTOR_PROVIDER_TIMEOUT_MS=30000` and can perform the initial structured JSON call, a strict JSON retry, and a plain-text rescue. Worst-case latency can approach 90s before a usable fallback reaches the learner.
- The live UI shows only `Thinking...` because production does not stream model tokens or meaningful phase events to the user. The current worktree has an SSE wrapper, but it still only emits `status: accepted` and a final payload after `handleAITutorPost` finishes.
- Several pre-provider and post-provider operations are serial in the request path, including authentication, quota lookup, database context, RAG evidence context, message recording, and usage recording. Some are already softened in the current worktree but not proven deployed to live.
