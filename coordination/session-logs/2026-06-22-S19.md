## Conclusion

Do not migrate away from Neon solely for stability right now. Current evidence supports: production is deployed, required env variable names are present, the public site/API are reachable, and public provider status is green. Current evidence does not yet prove: authenticated production storage health, Neon project-level latency, Postgres error rate, backup/restore readiness, or live classroom write stability.

The near-term risk is less "Neon vs Supabase" and more:

1. Region alignment: current code does not explicitly pin Vercel function regions; Vercel function traffic observed from Hong Kong routes through `iad1` in response headers. California users need Vercel server functions and the Postgres primary in the same/near US West region.
2. Verification gap: admin storage health needs an authenticated S19/S12/S11 smoke proving `provider: postgres`, `durableReady: true`, and stable login/session/write flows.
3. Storage model scaling: the current app still includes a Postgres `app_state` JSONB row path with row locking plus hot auth tables. Provider migration will not solve future write contention if the app needs many simultaneous teacher/student writes.

## Recommendation

- Keep Neon for now if the current Neon database is in AWS `us-west-2` or another US West-adjacent region and can pass the production admin smoke.
- Before any provider migration, run a 24-72 hour lightweight monitor: login, `/api/me`, assignment/practice write, storage health, p95 latency, and Postgres error rate.
- If California latency is poor, first align regions:
  - Vercel Functions: configure US West where supported, such as San Francisco/Portland region options.
  - Database: keep Neon in AWS `us-west-2` or evaluate Supabase `us-west-1` if a North California primary is materially better.
- Consider Supabase only if MAIS wants Supabase Auth/Storage/Realtime/RLS/admin console as a platform, or if North California database placement plus integrated backend services become more valuable than Neon branching/serverless ergonomics.
- For enterprise-grade future scale, compare AWS RDS/Aurora PostgreSQL as the conservative managed-Postgres baseline; it is likely more operationally mature, but also heavier to operate with Vercel.
