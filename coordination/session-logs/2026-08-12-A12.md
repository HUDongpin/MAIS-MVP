## Implementation handoff

- Added authoritative, abort-bounded PostgreSQL admission paths with independent one-connection lanes for auth, policy, and rate limiting; the general pool remains capped at two connections.
- Added an in-flight-only policy/rate connection primer. Auth completes its own query and transaction cleanup first; then policy/rate handshakes begin before their shorter stage clocks. Idle-closed sockets are re-primed on the next request.
- Disabled postgres.js dynamic array-type discovery only on the three scalar-only admission clients. Each cold `BEGIN` and transaction is protected by an end-to-end watchdog that destroys and replaces the one-slot client before releasing its lane; primer attempts share the same policy/rate slots, so an expired queued primer cannot terminate another request's active transaction.
- Added strict policy projection validation so malformed non-null records fail closed instead of normalizing to `open`.
- Added PostgreSQL schema v3 migration, classroom projection attestation, append-only tutor message/usage journals, narrow quota reads, and narrow message/usage writers.
- Kept immediate rollback compatibility through transactionally attested dual writes and a `BEFORE` compatibility trigger. Exact-v2 policy/quota readers remain able to read rollback-window data, and a later v3 roll-forward reconciles it without duplicate IDs.
- Avoided postgres.js 3.4.x `Query.cancel()` because its CancelRequest promise is not observable by callers; route aborts return promptly while transaction-local timeouts and rollback retain lane ownership until cleanup completes.
- Added a fail-closed PostgreSQL 16 integration harness and a dedicated PR/manual-full-validation CI job.
