# 2026-06-04 S19 SimpleTex Transient Failure Mitigation

## Analysis

- The observed SimpleTex `fetch failed` was a network/request-layer failure, not a stable credential or endpoint failure.
- Evidence: DNS lookup, TLS handshake, GET reachability, direct POST, default-timeout POST rerun, and post-change live POST all succeeded against `server.simpletex.cn`.
- The current route already falls back to Mathpix/Qwen/manual review when SimpleTex returns `null`, so the production risk was degraded OCR quality/latency rather than user-facing outage.
- The code previously logged the raw `Error` object and made only one SimpleTex request, which made transient socket/TLS failures harder to classify and recover from.

## Changes

- Added a bounded SimpleTex retry inside the handwriting-recognition route:
  - Default max attempts: `2`
  - Default retry delay: `350ms`
  - Retry only for transient request failures and retryable HTTP statuses `429` / `5xx`
  - Preserve the existing total provider timeout budget
  - Do not retry stable `4xx` auth/parameter errors
- Added redacted provider diagnostics for SimpleTex failures:
  - Host, attempt count, elapsed time, status/error class, and scrubbed body/error sample
  - Token-shaped strings are replaced with `[redacted-token]`
- Added optional non-secret env examples:
  - `HANDWRITING_RECOGNITION_SIMPLETEX_MAX_ATTEMPTS=2`
  - `HANDWRITING_RECOGNITION_SIMPLETEX_RETRY_DELAY_MS=350`

## Checks

- Passed: `npm run type-check`.
- Passed: direct SimpleTex live POST after the change, HTTP 200, parsed `status: true`, candidate text present, confidence about `0.82`, elapsed about `2.6s`.
- Attempted: `npm run build`; compile and type/lint phases passed, then build failed while prerendering unrelated `/mistake-book` with `ReferenceError: formatBarePoweredGroupsInPlainText is not defined`.

## Follow-Up

- S04/S22 should handle the unrelated `/mistake-book` prerender failure if standard build is required as a release gate.
- If SimpleTex transient failures recur in production after this retry, inspect the new redacted `host/attempt/elapsed/error class` diagnostics before changing credentials or provider order.
