# 2026-06-26 A02 Student Dashboard Photo Upload Bugfix

- Agent ID: A02 Dashboard lead.
- Objective: analyze and fix the student dashboard `Upload photo` button rejecting the owner's valid PNG avatar upload.
- Assignment/user report: Student dashboard profile upload shows `Choose a JPG, PNG, or WebP image under 5 MB.` for a PNG around 400 KB.
- Initial evidence: screenshot shows the profile panel upload validation error after choosing a photo; `components/dashboard/StudentProfilePanel.tsx` currently rejects before decoding unless `File.type` is exactly one of the accepted MIME strings.
- Current repo state: root worktree is already broadly dirty, including a pre-existing large diff in `components/dashboard/StudentProfilePanel.tsx`; no staging, branch, commit, reset, delete, or revert operations performed.
- Intended files to change: `components/dashboard/StudentProfilePanel.tsx`, new `components/dashboard/studentProfileAvatarUpload.ts`, new `components/dashboard/studentProfileAvatarUpload.test.ts`, and this A02 session log.
- Scope confirmation: files are A02 dashboard-owned; no backend/API/storage changes unless later evidence proves an A12-owned server boundary is failing.
- Plan:
  1. Add a focused regression test for valid PNG files whose browser MIME type is empty or legacy `image/x-png`.
  2. Replace the exact MIME-only client gate with a small helper that accepts known image MIME labels or safe file extensions under 5 MB.
  3. Rerun the focused test and TypeScript check if practical.

## Handoff

- Root cause: the student profile upload client gate in `StudentProfilePanel.tsx` only accepted exact MIME values via `avatarUploadAccept.split(",").includes(file.type)`. Valid PNG files can arrive from browser/file-picker paths with empty, generic, or legacy MIME labels even when the file is under 5 MB, so the client rejected the upload before image decoding.
- Fix: moved upload support checks into `components/dashboard/studentProfileAvatarUpload.ts`; the helper keeps the 5 MB limit, accepts standard/legacy image MIME labels, and falls back to `.jpg`, `.jpeg`, `.png`, or `.webp` extensions only when the MIME label is missing or generic. `StudentProfilePanel.tsx` now uses that helper and advertises file extensions in the `accept` attribute.
- Files changed by this A02 pass: `components/dashboard/StudentProfilePanel.tsx`, `components/dashboard/studentProfileAvatarUpload.ts`, `components/dashboard/studentProfileAvatarUpload.test.ts`, `coordination/session-logs/2026-06-26-A02.md`.
- Checks run:
  - `npx tsx --test components/dashboard/studentProfileAvatarUpload.test.ts` failed first because the helper did not exist, then passed with 3 tests.
  - One-off Playwright browser smoke on `http://127.0.0.1:3047`: logged in as Student Shirleen, uploaded a valid PNG buffer with `application/octet-stream`, confirmed `Photo selected`, confirmed `Save profile` enabled, and confirmed the validation error was hidden.
  - `npm run type-check` still fails in unrelated A06-owned visualization test contract: `components/visualizations/three/manim/mathCameraFramePayload.test.ts` references `orientationOrthonormalReady` and `orientationOrthonormalMaxError` fields missing from `CameraFramePayload`.
- Not run: full A11 E2E matrix, because this session is A02-owned and the existing student button matrix has older avatar-label expectations outside this targeted bugfix.
- Risk/follow-up: no backend/API changes were needed; server-side profile validation still receives the prepared JPEG data URL after successful client image decoding.
