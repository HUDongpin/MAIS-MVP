## Diagnosis

- Candidate timing logs showed hot authentication, classroom-policy, and PostgreSQL rate-limit stages completing within their admission budgets.
- The remaining delay came from two reads of the monolithic PostgreSQL `app_state.payload`: the token-quota lookup and the database-context lookup each parsed and normalized the full application snapshot.
- The prior JavaScript soft timeout used `Promise.race` only. A timed-out PostgreSQL lookup continued in the background and synchronous snapshot normalization could block the event loop, so the nominal one-second and 1.5-second budgets did not preserve enough time for Qwen.
- Generic `/practice` requests supplied no database-backed anchor or scope but still performed the full context snapshot read.

## Implementation

- Added a fail-open generic-context fast path at the persistence boundary. A database snapshot is now read only when the request explicitly provides a nonblank topic, question, lesson, target student, or authorized data scope.
- Added a PostgreSQL-only, parameterized JSONB aggregate for Nova token usage. It preserves the existing token accounting semantics while avoiding application-side full-snapshot parsing and normalization.
- Added an inner PostgreSQL `statement_timeout` that expires before the outer quota budget, plus `AbortSignal` propagation and pending-query cancellation for both setup and aggregate queries.
- Upgraded the resolver soft-timeout helper to create a child abort signal linked to request cancellation. A quota timeout cancels its own database work without aborting the later Qwen provider request.
- Preserved the existing snapshot fallback for non-PostgreSQL storage and for dependency hooks that explicitly return `undefined`.
- Updated the mocked provider to echo the requested model when a fixture omits it, matching the resolver's fail-closed Qwen model attestation.
- Added a harness-only four-second rate-limit admission budget for serial SQLite semantic tests. Production retains the two-second product default and continues to use the narrow PostgreSQL rate-limit table path.
