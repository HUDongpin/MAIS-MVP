- Date: 2026-06-23

- Workstream: Teacher Console online navigation latency
- Status: In progress
- Objective: Reduce the live `mais.hk` Teacher Console left-nav latency by removing repeated teacher authentication/foundation reads, skipping heavy empty-teacher aggregation, and deferring Reports preview work.

## Summary

- Reused cached teacher authentication and shell data through `getTeacherShellForLayout()` so the teacher layout and child pages can share the same authenticated shell read.
- Added an empty-teacher data path for the 12-button Teacher Console workspace. For Teacher Scott/no-class accounts, dashboard/classes/analytics/rewards/lesson kits/live/assignments/resources/assessments/reports/inbox/operations now avoid full foundation or page-specific aggregation where the cached shell already shows zero classes.
- Changed dashboard to pass an initial empty dashboard payload for no-class teachers, which prevents the client from starting `/api/teacher/dashboard` on first render.
- Kept Reports first render light by not eagerly generating a default report preview; the client requests previews only when a valid target exists.
- Kept no-class Rewards and Live views from starting background teacher API pressure (`TeacherGamificationPanel`, 5s live refresh polling).

## Risks

- All `/teacher/*` routes remain dynamic because the teacher area still reads cookies/auth. This fix removes avoidable work but does not make the pages static.
- Production latency can still be affected by Vercel/serverless cold starts, worker queuing, and production storage wake-up; S22 must verify live after a clean deployment.
- Teachers with real classes still need full foundation/page data for many pages; future work may need client-side workspace data sharing or API-level projection/caching for non-empty teachers.
- The previously observed global learning-event pressure has a local S08/S12 fix, but production still needs S22/S25 deployment and live retest evidence.
